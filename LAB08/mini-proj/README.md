# LAB08 - DCNN Model Comparison: Cat vs Dog

แหล่งข้อมูล:https://www.kaggle.com/datasets/tongpython/cat-and-dog

## 1. Objective

LAB08 เป็นการทดลอง Deep Convolutional Neural Network (DCNN) สำหรับจำแนกรูปภาพ 2 คลาส คือ **Cat** และ **Dog** โดยเปรียบเทียบ DCNN ที่มีสถาปัตยกรรมแตกต่างกันจำนวน 6 โมเดล ได้แก่ VGG16, VGG19, InceptionV3, ResNet101, MobileNetV2 และ EfficientNetB0

การทดลองเน้นการเปรียบเทียบผลจาก Training Accuracy, Validation Accuracy, Loss, Test Accuracy และจำนวน Parameters ตามแนวทางของใบงานที่ให้สร้าง DCNN, ทดลองจำนวน Epoch และเปรียบเทียบประสิทธิภาพของโมเดล

---

## 2. Dataset

ใช้ Dataset Cat and Dog สำหรับงาน Image Classification และแบ่งข้อมูลเป็น Training, Validation และ Test set

ในการทดลองนี้มีข้อมูลรวม **7,894 รูป**

- Cat: 3,889 รูป
- Dog: 4,005 รูป
- Training: 5,525 รูป
- Validation: 1,183 รูป
- Test: 1,186 รูป

---

## 3. Models ที่เลือกใช้

เลือก 6 โมเดลเพื่อให้เห็นความแตกต่างของ DCNN หลายรูปแบบ ทั้งโมเดลที่มีความลึกและขนาดใหญ่ โมเดลที่ใช้โครงสร้างแบบ multi-scale และโมเดลที่เน้นความมีประสิทธิภาพ/ขนาดเล็ก

### 3.1 VGG16

**แนวคิด:** ใช้ convolutional layers หลายชั้นเรียงต่อกัน โดยใช้ kernel ขนาดเล็กและโครงสร้างที่ค่อนข้างเป็นลำดับ ทำให้เป็นสถาปัตยกรรมที่เข้าใจง่ายและเหมาะสำหรับใช้เป็น baseline ในการเปรียบเทียบ

**ข้อดี**
- โครงสร้างเข้าใจง่ายและเป็นที่รู้จักอย่างแพร่หลาย
- สามารถเรียนรู้ feature ของภาพได้ดี
- ผลการทดลองครั้งนี้มี Validation Accuracy สูงสุดที่ **99.58%**
- Test Accuracy สูงถึง **99.07%**

**ข้อเสีย**
- มีจำนวน Parameters สูงมากเมื่อเทียบกับโมเดลขนาดเล็ก
- ใช้หน่วยความจำและเวลาในการประมวลผลมากกว่าโมเดลเบา
- ไม่เหมาะเท่าโมเดลขนาดเล็กหากต้องนำไปใช้งานบนอุปกรณ์ที่มีทรัพยากรจำกัด

**เหตุผลที่เลือก:** ใช้เป็นตัวแทนของ DCNN ที่มีโครงสร้างแบบลึกและเป็น baseline สำหรับเปรียบเทียบกับโมเดลสมัยใหม่

---

### 3.2 VGG19

**แนวคิด:** มีโครงสร้างคล้าย VGG16 แต่เพิ่มความลึกของเครือข่าย ทำให้สามารถเรียนรู้ feature ที่ซับซ้อนขึ้นได้

**ข้อดี**
- โครงสร้างต่อยอดจาก VGG16 ได้ง่าย
- ความลึกมากขึ้นทำให้สามารถเรียนรู้ feature หลายระดับได้
- เหมาะสำหรับใช้เปรียบเทียบผลของการเพิ่มความลึกจาก VGG16

**ข้อเสีย**
- ความลึกที่เพิ่มขึ้นไม่ได้รับประกันว่าจะให้ผลดีกว่าเสมอไป
- ใช้ทรัพยากรมากขึ้นในสถาปัตยกรรม VGG โดยทั่วไป
- ในการทดลองครั้งนี้ Test Accuracy อยู่ที่เพียง **82.72%** ซึ่งต่ำกว่า VGG16 มาก

**เหตุผลที่เลือก:** เพื่อเปรียบเทียบโดยตรงว่าเมื่อเพิ่มความลึกจาก VGG16 เป็น VGG19 ผลการจำแนกจะดีขึ้นหรือไม่

---

### 3.3 InceptionV3

**แนวคิด:** ใช้โครงสร้าง Inception ที่ประมวลผล feature หลายขนาดภายในเครือข่าย ทำให้สามารถมองเห็นลักษณะของภาพในหลายระดับ

**ข้อดี**
- สามารถเรียนรู้ feature หลายขนาดได้
- มีประสิทธิภาพดีสำหรับงาน Image Classification
- ในการทดลองครั้งนี้ได้ Test Accuracy **94.18%** ซึ่งเป็นอันดับที่ 3
- Validation Accuracy เพิ่มขึ้นต่อเนื่องจนถึง **92.48%**

**ข้อเสีย**
- โครงสร้างซับซ้อนกว่า VGG
- ต้องใช้การประมวลผลและการจัดการโมเดลมากกว่าโมเดลที่โครงสร้างเรียบง่าย
- ผลการทดลองยังต่ำกว่า VGG16 และ EfficientNetB0

**เหตุผลที่เลือก:** เพื่อเปรียบเทียบสถาปัตยกรรมที่ใช้การประมวลผล feature หลายขนาดกับสถาปัตยกรรมแบบ VGG และโมเดลประเภทอื่น

---

### 3.4 ResNet101

**แนวคิด:** ใช้ Residual/Skip Connections เพื่อช่วยให้การฝึกเครือข่ายที่มีความลึกมากสามารถทำได้ดีขึ้น และช่วยลดปัญหาที่เกิดจากการเพิ่มจำนวนชั้น

**ข้อดี**
- สามารถสร้างเครือข่ายที่ลึกมากได้
- Residual connection ช่วยให้การส่งผ่านข้อมูลและ gradient ในเครือข่ายลึกทำได้ดีขึ้น
- เป็นสถาปัตยกรรมสำคัญสำหรับการเปรียบเทียบ DCNN แบบ deep network

**ข้อเสีย**
- มีความซับซ้อนและใช้ทรัพยากรมากกว่าโมเดลขนาดเล็ก
- ResNet101 ลึกมากเมื่อเทียบกับโมเดลอื่นในการทดลอง
- ผลการทดลองครั้งนี้ได้ Test Accuracy เพียง **64.59%**

**เหตุผลที่เลือก:** เพื่อทดสอบว่าเครือข่ายที่ลึกมากและมี Residual Connections จะให้ผลดีกับ Dataset นี้หรือไม่

---

### 3.5 MobileNetV2

**แนวคิด:** ออกแบบมาให้มีขนาดเล็กและใช้ทรัพยากรต่ำ เหมาะกับงานที่ต้องการนำ Deep Learning ไปใช้บนอุปกรณ์ที่มีข้อจำกัดด้าน CPU, Memory หรือพลังงาน

**ข้อดี**
- โมเดลมีขนาดเล็ก
- ใช้ทรัพยากรน้อยกว่าโมเดลขนาดใหญ่
- เหมาะสำหรับงานบนอุปกรณ์ Edge หรือ Mobile
- จำนวน Parameters ที่รายงานในการทดลองประมาณ **4.21 ล้าน**

**ข้อเสีย**
- ในการทดลองครั้งนี้ได้ Test Accuracy เพียง **50.76%** ซึ่งต่ำที่สุด
- Validation Accuracy อยู่ประมาณ **50.72%**
- แสดงว่า configuration/preprocessing ที่ใช้ในการทดลองนี้ไม่สามารถทำให้ MobileNetV2 เรียนรู้ Dataset ได้ดี

**เหตุผลที่เลือก:** เพื่อเปรียบเทียบกับโมเดลใหญ่ และดู trade-off ระหว่างความแม่นยำกับขนาดของโมเดล

---

### 3.6 EfficientNetB0

**แนวคิด:** ออกแบบให้เพิ่มประสิทธิภาพของโมเดลโดยคำนึงถึงความสมดุลระหว่างความลึก ความกว้าง และความละเอียดของภาพ ทำให้ได้โมเดลที่มีขนาดค่อนข้างเล็กแต่สามารถให้ประสิทธิภาพสูง

**ข้อดี**
- โมเดลมีขนาดเล็กเมื่อเทียบกับโมเดลขนาดใหญ่
- จำนวน Parameters ในการทดลองประมาณ **4.21 ล้าน**
- Test Accuracy สูงถึง **99.07%**
- ได้ Accuracy เท่ากับ VGG16 แต่ใช้ Parameters น้อยกว่ามาก
- เป็นตัวอย่างที่ดีของการเน้นประสิทธิภาพต่อทรัพยากร

**ข้อเสีย**
- โครงสร้างภายในซับซ้อนและอธิบายยากกว่า VGG
- ประสิทธิภาพขึ้นอยู่กับ preprocessing และ configuration ที่ถูกต้อง

**เหตุผลที่เลือก:** เพื่อเปรียบเทียบโมเดลที่เน้น efficiency กับโมเดลขนาดใหญ่ และดูว่าโมเดลขนาดเล็กสามารถให้ Accuracy สูงได้หรือไม่

## 5. ทำไม VGG16 และ EfficientNetB0 จึงได้ผลดีที่สุด

จากผลการทดลอง **VGG16 และ EfficientNetB0 มี Test Accuracy สูงสุดเท่ากันที่ 99.07%** และมี Validation Accuracy สูงมากเช่นกัน

VGG16 สามารถจำแนกภาพได้ดี เนื่องจากมี convolutional layers หลายระดับที่สามารถเรียนรู้ feature จากภาพตั้งแต่ลักษณะพื้นฐานไปจนถึงลักษณะที่ซับซ้อนขึ้น และเป็นโครงสร้างที่เหมาะกับงาน Image Classification

EfficientNetB0 ให้ผลดีเช่นกัน แต่มีขนาดเล็กกว่ามาก โดยมี Parameters ประมาณ 4.21 ล้าน เทียบกับ VGG16 ประมาณ 42.92 ล้านตามผลการทดลอง จึงแสดงให้เห็นว่า **โมเดลที่มีขนาดเล็กกว่าไม่จำเป็นต้องมี Accuracy ต่ำกว่าเสมอไป**

ถ้าพิจารณาเฉพาะ Accuracy ทั้งสองโมเดลเสมอกัน แต่ถ้าพิจารณา Accuracy ร่วมกับขนาดโมเดล EfficientNetB0 มีความน่าสนใจมากกว่า เพราะให้ผลเท่ากันด้วยจำนวน Parameters ที่น้อยกว่ามาก

---

## 6. ทำไม MobileNetV2 จึงได้ผลแย่ที่สุด

MobileNetV2 ได้ Test Accuracy เพียง **50.76%** และ Validation Accuracy **50.72%** ซึ่งต่ำที่สุดในการทดลอง และใกล้เคียงกับการจำแนกแบบสุ่มสำหรับปัญหา 2 คลาส

อย่างไรก็ตาม **ไม่ควรสรุปว่า MobileNetV2 เป็นสถาปัตยกรรมที่แย่ที่สุดโดยทั่วไป** เพราะผลนี้เป็นผลเฉพาะจาก configuration และ preprocessing ของการทดลองนี้

สังเกตว่ารูปแบบผลลัพธ์ของโมเดลหลายตัวแตกต่างกันมาก เช่น VGG16/EfficientNetB0 ทำได้ประมาณ 99% ขณะที่ MobileNetV2 อยู่ประมาณ 50% จึงมีความเป็นไปได้สูงว่า **preprocessing ของ input ไม่เหมาะกับโมเดลบางตัว โดยเฉพาะโมเดลที่ใช้ pretrained ImageNet weights** เพราะแต่ละสถาปัตยกรรมอาจคาดหวังรูปแบบการ normalize input ที่แตกต่างกัน

ดังนั้นผล MobileNetV2 ครั้งนี้ควรตีความว่า **configuration ที่ใช้ในการทดลองยังไม่เหมาะกับ MobileNetV2** มากกว่าจะสรุปว่า MobileNetV2 มีประสิทธิภาพต่ำเสมอ

---

## 7. เปรียบเทียบทั้ง 6 โมเดล

### ด้าน Accuracy

**VGG16 ≈ EfficientNetB0 > InceptionV3 > VGG19 > ResNet101 > MobileNetV2**

โดย VGG16 และ EfficientNetB0 ได้ Test Accuracy เท่ากันที่ 99.07%

### ด้านขนาดโมเดล

จากจำนวน Parameters ที่รายงานในการทดลอง VGG16 มีขนาดใหญ่ที่สุด ขณะที่ EfficientNetB0 และ MobileNetV2 มีขนาดเล็กกว่าอย่างมาก

ดังนั้นการเลือกโมเดลไม่ได้ดู Accuracy เพียงอย่างเดียว แต่ควรพิจารณา **Accuracy, Loss, Parameters และทรัพยากรที่ต้องใช้** ร่วมกัน

### ด้านการเรียนรู้

- VGG16 และ EfficientNetB0 เรียนรู้ได้เร็วและไปถึง Accuracy สูงมาก
- InceptionV3 เรียนรู้ได้ดีแต่ยังต่ำกว่าสองโมเดลที่ดีที่สุด
- VGG19 มีการเพิ่ม Accuracy แต่ Validation Accuracy ยังอยู่ประมาณ 81%
- ResNet101 มีการเรียนรู้ดีขึ้นตาม Epoch แต่ยังมี Accuracy ต่ำ
- MobileNetV2 แทบไม่สามารถแยกสองคลาสได้จาก configuration นี้

## 8. สรุปผลการทดลอง

การทดลองเปรียบเทียบ DCNN จำนวน 6 โมเดลแสดงให้เห็นว่า **สถาปัตยกรรมของโมเดลมีผลต่อประสิทธิภาพอย่างชัดเจน** แม้จะใช้ Dataset เดียวกันและทำการ Train ในลักษณะเดียวกัน

โมเดลที่ให้ผลดีที่สุดด้าน Test Accuracy คือ **VGG16 และ EfficientNetB0 ที่ 99.07% เท่ากัน** แต่ EfficientNetB0 มีจำนวน Parameters น้อยกว่า VGG16 มาก จึงมีข้อได้เปรียบด้านขนาดและประสิทธิภาพต่อทรัพยากร

ในทางกลับกัน MobileNetV2 ให้ผลต่ำที่สุดที่ 50.76% และ ResNet101 ได้ 64.59% อย่างไรก็ตามผลที่ต่ำไม่ควรถูกตีความว่าเป็นข้อจำกัดของสถาปัตยกรรมเพียงอย่างเดียว เนื่องจาก preprocessing, pretrained weights, learning rate และ configuration ของการทดลองสามารถส่งผลต่อ Accuracy ได้มาก

ดังนั้นจากการทดลองนี้ หากต้องเลือกโมเดลสำหรับงาน Cat vs Dog โดยเน้น **Accuracy สูงและขนาดโมเดลไม่ใหญ่เกินไป** จะเลือก **EfficientNetB0** เป็นตัวเลือกที่น่าสนใจที่สุด ส่วน **VGG16** เหมาะสำหรับใช้เป็น baseline ที่ให้ Accuracy สูงและอธิบายโครงสร้างได้ง่าย

```text
กราฟเปรียบเทียบ + model_comparison.csv
```

### 8.1 `split_data.py` — แบ่ง Dataset

ไฟล์นี้ทำหน้าที่นำรูปภาพต้นฉบับจาก `PetImages/cat` และ `PetImages/dog` มาแบ่งออกเป็น 3 ชุด ได้แก่

- **Train** 70% — ใช้สำหรับให้โมเดลเรียนรู้
- **Validation** 15% — ใช้ตรวจสอบผลระหว่างการ Train และเลือก Epoch ที่เหมาะสม
- **Test** 15% — ใช้ทดสอบโมเดลหลังจาก Train เสร็จแล้ว

ผลลัพธ์จะถูกสร้างไว้ในโฟลเดอร์ `split_data/` โดยแยกเป็น `train`, `val` และ `test` และภายในแต่ละโฟลเดอร์จะแยก `cat` กับ `dog`

### 8.2 `data_loader.py` — โหลด Dataset

ไฟล์นี้ทำหน้าที่โหลดรูปภาพจาก `split_data/` ด้วย TensorFlow/Keras และจัดรูปข้อมูลให้พร้อมสำหรับการ Train โดยกำหนดขนาดภาพและ Batch Size ให้เหมือนกันทุกโมเดล เพื่อให้การเปรียบเทียบมีเงื่อนไขใกล้เคียงกัน

ในการทดลองนี้ใช้ภาพขนาด **224×224 pixels** และ Batch Size **32**

### 8.3 `preprocessing.py` — เตรียมข้อมูลก่อนเข้าโมเดล

ไฟล์นี้เกี่ยวข้องกับการเตรียม Input ให้เหมาะกับการนำไป Train โดยใช้ขั้นตอน preprocessing/normalization ตามที่กำหนดในโปรเจกต์ เพื่อให้ค่าของภาพอยู่ในรูปแบบที่โมเดลสามารถนำไปประมวลผลได้

> หมายเหตุ: โมเดลที่ใช้ pretrained ImageNet อาจมีข้อกำหนด preprocessing ที่แตกต่างกันตามสถาปัตยกรรม ดังนั้นผลของแต่ละโมเดลควรพิจารณาร่วมกับ configuration ที่ใช้จริงในการทดลอง ไม่ควรสรุปจากชื่อโมเดลเพียงอย่างเดียว

### 8.4 ไฟล์ในโฟลเดอร์ `models/` — สร้างโมเดลแต่ละชนิด

ในโปรเจกต์มีไฟล์สำหรับโมเดล 6 ตัว โดยแต่ละไฟล์ทำหน้าที่สร้างสถาปัตยกรรมของโมเดลนั้น ๆ และใช้ pretrained weights จาก ImageNet เป็นฐาน

#### `models/vgg16_model.py`
สร้างโมเดล VGG16 ซึ่งมีโครงสร้าง Convolutional layers หลายชั้นและเป็นโมเดลที่มีขนาดค่อนข้างใหญ่ จุดเด่นคือโครงสร้างเข้าใจง่ายและให้ผลดีมากในการทดลองนี้

#### `models/vgg19_model.py`
สร้าง VGG19 ซึ่งเป็นสถาปัตยกรรมในตระกูล VGG ที่ลึกกว่า VGG16 จุดประสงค์ของการนำมาใช้คือเพื่อเปรียบเทียบว่าเมื่อใช้ VGG ที่ลึกขึ้น ผลจะดีขึ้นหรือไม่ภายใต้การทดลองเดียวกัน

#### `models/inceptionv3_model.py`
สร้าง InceptionV3 ซึ่งใช้โครงสร้างแบบ Inception ที่ประมวลผล Feature หลายขนาดภายในเครือข่าย เหมาะสำหรับใช้เปรียบเทียบกับ VGG และ ResNet ที่มีแนวทางการออกแบบต่างกัน

#### `models/resnet101_model.py`
สร้าง ResNet101 ซึ่งเป็นโมเดลที่มีความลึกมากและใช้แนวคิด Residual Connection เพื่อช่วยให้การฝึกเครือข่ายลึกทำได้ดีขึ้น จุดประสงค์ในการทดลองคือเปรียบเทียบผลของโมเดลที่ลึกมากกับโมเดลประเภทอื่น

#### `models/mobilenetv2_model.py`
สร้าง MobileNetV2 ซึ่งออกแบบมาให้มีขนาดเล็กและใช้ทรัพยากรน้อยกว่าโมเดลขนาดใหญ่ เหมาะกับงานที่ต้องการลดขนาดโมเดลหรือใช้งานบนอุปกรณ์ที่มีทรัพยากรจำกัด

#### `models/efficientnetb0_model.py`
สร้าง EfficientNetB0 ซึ่งเน้นการสร้างสมดุลระหว่างความแม่นยำและขนาดโมเดล จุดประสงค์สำคัญในการทดลองคือเปรียบเทียบกับ VGG16 ว่าสามารถให้ Accuracy สูงได้โดยใช้ Parameters น้อยกว่าหรือไม่

### 8.5 `train_models.py` — ไฟล์หลักสำหรับ Train

ไฟล์นี้เป็นตัวควบคุมการทดลองหลัก โดยจะโหลด Dataset แล้วเรียกใช้โมเดลทั้ง 6 ตัวทีละตัว จากนั้น Train และประเมินผลแต่ละโมเดล

การตั้งค่าหลักของการทดลองนี้คือ:

- Epoch สูงสุด = **10**
- Optimizer = **Adam**
- Learning Rate = **0.0001**
- Loss = **Binary Crossentropy**
- Metric = **Accuracy**
- ใช้ **EarlyStopping** เพื่อหยุดก่อนครบ Epoch หาก Validation ไม่ดีขึ้น
- ใช้ **ReduceLROnPlateau** เพื่อปรับ Learning Rate เมื่อผล Validation ไม่ดีขึ้น

โมเดลแต่ละตัวใช้ pretrained base จาก ImageNet และในช่วงการทดลองนี้ Base model ถูก Freeze แล้วฝึก Classification Head ด้านบน ซึ่งเป็นแนวทางของ Transfer Learning

หลัง Train แต่ละโมเดลจะบันทึกข้อมูล เช่น:

- `history.json` — ค่า Accuracy/Loss ในแต่ละ Epoch
- `metrics.json` — ผลการประเมินของโมเดล
- ไฟล์ `.keras` — โมเดลที่ Train แล้ว
- กราฟ Training/Validation Accuracy และ Loss

### 8.6 โฟลเดอร์ `outputs/` — เก็บผลลัพธ์ของแต่ละโมเดล

ภายใน `outputs/` จะมีโฟลเดอร์แยกตามโมเดล เช่น `vgg16`, `vgg19`, `inceptionv3`, `resnet101`, `mobilenetv2` และ `efficientnetb0` เพื่อไม่ให้ผลของแต่ละโมเดลปะปนกัน

ข้อมูลในโฟลเดอร์นี้เป็นผลลัพธ์ที่ใช้ในการสร้างตารางและกราฟเปรียบเทียบ

### 8.7 `compare_models.py` — เปรียบเทียบทั้ง 6 โมเดล

หลังจาก Train ครบแล้ว ไฟล์นี้จะอ่านผลลัพธ์จาก `outputs/` แล้วนำมาสรุปรวมเป็นตารางเดียว เพื่อดูว่าโมเดลใดทำได้ดีที่สุดและโมเดลใดทำได้ต่ำที่สุด

ผลลัพธ์ที่สร้าง ได้แก่:

- `model_comparison.csv`
- `comparison_training_accuracy.png`
- `comparison_validation_accuracy.png`
- `comparison_training_loss.png`
- `comparison_validation_loss.png`
- `comparison_test_accuracy.png`

ดังนั้น `compare_models.py` **ไม่ใช่การ Train ใหม่** แต่เป็นขั้นตอนวิเคราะห์และเปรียบเทียบผลที่ Train เสร็จแล้ว

### 8.10 ผลที่ได้จากการทดลองนี้
